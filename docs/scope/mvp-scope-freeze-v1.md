## 1. 目标

真实用户能完成：注册 → 创建站点 → 编辑或上传 HTML/CSS/JS → 原子发布 → 独立子域访问 → Explore → Follow。

邀请测试不要求对齐 Nekoweb 的每一项功能。对外邀请以第 9 节 Gate（安全、恢复、运营）为准，不以日期为准。

## 4. 不可放宽的安全不变量

1. **域隔离**：控制面（`app.example.com`）与用户站点（`*.sites-example.net`）使用不同注册域；控制面 Cookie 为 host-only、HttpOnly、Secure、SameSite，不设置 `Domain`。
2. **不在平台域执行用户代码**：控制面不直接插入用户 HTML，不用同源 iframe 预览；站点卡片不抓取用户站点。
3. **服务端授权**：每个写入口都校验登录、`owner_id`、`site_id` 和站点状态；敏感写请求校验 Origin/CSRF。
4. **Gateway 最小权限**：仅 GET/HEAD；数据库只读账户；对象存储只读，没有写桶权限。
5. **路径规范化**：URL 只解码一次；非法编码、NUL、反斜杠、空段、`.`、`..` 一律拒绝；TS 与 Go 共用同一组测试向量。
6. **发布原子性**：部署清单不可修改；只有 READY 部署可以成为 current；切换在单个数据库事务内完成；失败时保留旧指针。
7. **可恢复**：数据库与对象存储一起备份、一起演练恢复；回滚目标的对象缺失时拒绝回滚并报警。
8. **不存明文密钥**：Session/Token 只存哈希；日志不含明文 Token；仓库不提交密钥。

## 6. 验收用户故事

1. 用户验证邮箱并登录，创建 `alice` 站点；编辑 `index.html`、`style.css`、`script.js`，并上传一张图片。
2. 用户发布后可在 `alice.<站点域>` 访问；错误版本可以回滚；已经打开的浏览器在规定缓存窗口后看到新版本。
3. 另一用户在 Explore 找到该站点并 Follow；恶意站点代码无法读取控制面 Session，也无法读取其他站点的文件。
