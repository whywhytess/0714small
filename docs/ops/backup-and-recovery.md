# 备份与恢复目标

- 日期：2026-09-24（W0 Day 5）
- 依据：计划第 3、8、9 节；[ADR 0005](../adr/0005-s3-object-storage.md)、[ADR 0006](../adr/0006-immutable-deployments.md)、[ADR 0007](../adr/0007-providers-and-environments.md)
- 首次演练：**W7 Day 3**（隔离环境）。邀请用户前必须演练通过。

## 目标（建议值，待本人确认）

| 指标 | 目标 |
|---|---|
| RPO：最多丢失多少数据 | ≤ 15 分钟 |
| RTO：多久恢复服务 | ≤ 4 小时 |
| PostgreSQL PITR 窗口 | 7 天 |
| 每日快照保留 | 14 天 |
| S3 非当前版本保留 | 30 天 |
| 部署保留 | 每个站点最近 10 个或 30 天内的部署 |

## 备份什么

| 数据 | 方式 | 说明 |
|---|---|---|
| PostgreSQL | 托管服务的 PITR + 每日快照 | 包括 users、sessions、sites、draft_files、deployments、deployment_files 等所有表 |
| 对象存储 | S3 Versioning + 生命周期规则 | 对象键不会被覆盖（ADR 0002），所以版本控制主要防的是误删 |
| 配置与密钥 | 平台的密钥管理 | 不进 git；另外记一份离线清单，写明“哪些密钥存在哪里”，不写密钥的值 |
| 代码 | GitHub | 迁移文件也在仓库里 |

**关键一致性：** 数据库里的对象引用（`object_key`）必须能在恢复出来的存储里找到。所以对象的保留期必须**长于** PITR 窗口加上部署保留期，这样恢复到任何时间点时，被引用的对象都还在。

## 恢复演练步骤（W7 Day 3 细化）

1. 在隔离的环境里，把 PostgreSQL 恢复到指定时间点 T。
2. 让隔离环境的 Gateway 指向恢复出来的数据库，以及存储（使用对象的历史版本）。
3. 随机抽查 N 个站点：`current_deployment_id` 对应的所有 `object_key` 都能读到。
4. 记录耗时、没能恢复的项目和原因。
5. 结果写入 devlog 和第 9 节 Gate 的证据。

## 访问控制

- 备份和恢复使用单独的凭据，**不部署到应用里**。
- 只有本人能执行恢复和删除备份。
- 删除备份需要二次确认；有条件时开启 S3 Object Lock 或供应商提供的删除保护。
