# 0005. 私有 S3 兼容对象存储

- 状态：提议
- 日期：2026-09-24

## 背景

用户文件要能可靠保存、可以恢复，而且不能被直接公开访问：必须经过 Gateway 的 Host、路径和站点状态检查。

## 决定

1. **生产环境暂定 AWS S3**，使用私有桶，并开启 **Block Public Access** 和**对象版本控制（Versioning）**。
2. 代码只使用 S3 兼容 API 的一个小子集：`PutObject`、`GetObject`、`HeadObject`、`DeleteObject`、`ListObjectsV2`。不依赖某个供应商的专有功能。
3. **本地和 CI 使用 MinIO**，镜像固定到具体版本（MinIO 社区版已不再持续发布新镜像，所以固定一个已知可用的 tag，并记录在 `infra/compose`）。
4. 按用途分离凭据：
   - 控制面：读写 `sites/*`
   - Gateway：只读
   - 备份和恢复：单独的凭据，不部署到应用里
5. 版本控制配合生命周期规则：非当前版本保留 N 天（在 [0007](0007-providers-and-environments.md) 里确定），用来防止误删和在恢复时使用。
6. 以后要更换供应商（如 R2），必须先评估恢复能力、版本控制支持和成本，并新写一个 ADR。

## 后果

- 所有对站点文件的读取都经过 Gateway，没有公开的桶 URL。
- 开启版本控制会增加存储量，需要算进预算。
- MinIO 和 S3 的行为有差异（例如条件写入、错误码），这些差异点需要在 staging 上用真实 S3 验证。

## 被否决的方案

- **公开桶 + CDN 直连**：绕过了站点暂停和路径规则。
- **数据库 BLOB 存文件**：会让备份、复制和数据库负载都变得很重。
